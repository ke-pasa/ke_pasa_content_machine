# 🏗️ ПЛАН ОПТИМИЗАЦИИ АРХИТЕКТУРЫ RSS-БОТА

## 📊 ТЕКУЩАЯ ПРОБЛЕМА
Система генерирует Telegram посты для ВСЕХ статей (468), но публикует только 2-6 в день.
**Результат:** Трата токенов на неиспользуемые посты.

## 🎯 НОВАЯ АРХИТЕКТУРА

### Этап 1: Сбор и фильтрация
```
RSS Парсинг → LLM Фильтрация → Сохранение статьи (БЕЗ Telegram поста)
```
- Сохраняем только: заголовок, текст, приоритет, изображение
- **НЕ генерируем** Telegram посты

### Этап 2: Кластеризация (улучшенная)
```
Статьи → Группировка похожих → Создание кластеров → Генерация контента
```
- Кластеры получают бонус +10 к приоритету
- Создается одна статья из нескольких источников

### Этап 3: Ежедневное планирование
```
Планировщик → Выбор топ-6 статей → Генерация Telegram постов → Планирование публикации
```
- **Только тогда** генерируем Telegram посты
- Экономия токенов: в 78 раз (468/6 = 78)

### Этап 4: Публикация
```
Окна публикации → Отправка в Telegram → Отметка как опубликовано
```

## 💡 ПРЕИМУЩЕСТВА НОВОЙ АРХИТЕКТУРЫ

### 🔥 Экономия токенов
- **Было:** 468 Telegram постов = ~468k токенов
- **Станет:** 6 Telegram постов = ~6k токенов  
- **Экономия:** 98.7% токенов на Telegram посты

### ⚡ Повышение качества
- Посты генерируются только для лучших статей
- Больше внимания к качеству каждого поста
- Возможность A/B тестирования постов

### 🎯 Лучшее планирование
- Выбор статей основан на актуальных приоритетах
- Учет времени дня и аудитории
- Балансировка тематик

## 🛠️ ПЛАН РЕАЛИЗАЦИИ

### Фаза 1: Отключение автогенерации постов
1. Убрать генерацию Telegram постов из `rss_parser.py`
2. Сохранять статьи без поля `telegram_post`
3. Тестировать сбор статей

### Фаза 2: Создание умного планировщика
1. Создать `daily_post_planner.py`
2. Логика выбора топ-статей на день
3. Генерация постов только для выбранных

### Фаза 3: Интеграция с кластеризацией
1. Исправить ошибку кластеризации
2. Приоритизация кластеров
3. Тестирование полного цикла

### Фаза 4: Тонкая настройка
1. Балансировка тематик
2. Учет времени публикации
3. Аналитика эффективности
