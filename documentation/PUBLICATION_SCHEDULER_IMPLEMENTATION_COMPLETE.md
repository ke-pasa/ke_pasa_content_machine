# Отчет о завершении: Модуль планирования публикаций

## ✅ Задача выполнена

Реализован модуль `publication_scheduler.py` для автоматического планирования публикаций на основе приоритезированных кластеров новостей для RSS-бота русскоязычных мигрантов в Испании.

## 📋 Что было реализовано

### 1. Основной класс `PublicationScheduler`

**Ключевые возможности:**
- Автоматическое планирование публикаций по фиксированному расписанию
- Обработка срочных новостей вне очереди
- Создание дайджестов из неиспользованных кластеров
- Интеграция с Firebase для хранения jobs
- Поддержка часового пояса Europe/Madrid

**Основные методы:**
- `schedule_publications()` - планирование публикаций на день
- `schedule_urgent()` - немедленная публикация срочных новостей
- `create_digest_job()` - создание дайджеста
- `get_scheduled_jobs()` - получение запланированных jobs
- `update_job_status()` - обновление статуса job

### 2. Структура данных

**Класс `PublicationSlot`:**
```python
@dataclass
class PublicationSlot:
    time: str  # HH:MM
    datetime: datetime
    max_articles: int
    used_articles: int = 0
    scheduled_clusters: List[str] = None
```

**Структура job в Firebase:**
```json
{
  "job_id": "auto_2025-08-03_09-00",
  "cluster_id": "abc123",
  "planned_at": "2025-08-03T09:00:00Z",
  "channel": "telegram",
  "urgent": false,
  "status": "scheduled",
  "priority_score": 83,
  "event_type": "policy_change",
  "created_at": "...",
  "type": "post",
  "sensitivity_level": "normal"
}
```

### 3. Стратегия планирования

**Фиксированное расписание:**
- 09:00, 14:00, 20:00 по испанскому времени
- Максимум 2 статьи на публикацию (настраивается)
- Порог приоритета 60 баллов (настраивается)

**Логика отбора:**
1. **Срочные новости** - публикуются немедленно
2. **Обычные новости** - по расписанию с учетом:
   - Приоритета (priority_score >= threshold)
   - Чувствительности (не более одного "high" в день)
   - Типа события (не повторять event_type подряд)
3. **Дайджест** - в 21:30 из неиспользованных кластеров

### 4. Интеграция с Firebase

**Настройки из коллекции settings:**
```json
{
  "publishing_times": ["09:00", "14:00", "20:00"],
  "max_articles_per_post": 2,
  "priority_threshold": 60
}
```

**Коллекция jobs:**
- Уникальные job_id для каждого задания
- Статусы: scheduled, sent, skipped, deferred
- Поддержка срочных публикаций (urgent_post)
- Дайджесты (type: digest)

### 5. Обработка ошибок и логирование

**Встроенное логирование:**
- Информационные сообщения о создании jobs
- Предупреждения о недоступности настроек
- Ошибки при сохранении в Firebase

**Fallback логика:**
- Использование дефолтных настроек при недоступности Firebase
- Graceful handling ошибок подключения

## 📊 Примеры использования

### Планирование на день
```python
from publication_scheduler import create_publication_scheduler
from firebase_client import get_firebase_client

firebase_client = get_firebase_client()
scheduler = create_publication_scheduler(firebase_client)

# Планируем публикации на завтра
jobs = scheduler.schedule_publications(clusters, "2025-01-30")
print(f"Запланировано {len(jobs)} публикаций")
```

### Срочная публикация
```python
# Немедленная публикация срочной новости
urgent_job = scheduler.schedule_urgent(urgent_cluster)
if urgent_job:
    print(f"Срочная публикация запланирована: {urgent_job['job_id']}")
```

### Получение запланированных jobs
```python
# Получаем все запланированные jobs на сегодня
scheduled_jobs = scheduler.get_scheduled_jobs("2025-01-30", "scheduled")
for job in scheduled_jobs:
    print(f"Job: {job['job_id']} в {job['planned_at']}")
```

## 🔐 Важные особенности

### Антидублирование
- Проверка существующих jobs перед созданием новых
- Уникальные job_id на основе cluster_id и времени
- Исключение повторных event_type в один день

### Ограничения чувствительности
- Не более одного "high" sensitivity в день
- Избежание публикации нескольких чувствительных тем подряд
- Учет sensitivity_level при планировании

### Гибкость настроек
- Все параметры настраиваются через Firebase
- Fallback на дефолтные значения
- Поддержка изменения расписания без перезапуска
