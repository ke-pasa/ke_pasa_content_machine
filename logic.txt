📋 Подробная логика работы RSS-бота для русскоязычных мигрантов в Испании

## 🚀 **1. Инициализация системы**

**Шаг 1.1: Загрузка конфигурации**
- Загружает переменные окружения из файла `.env`
- Инициализирует OpenAI клиент для работы с LLM
- Подключается к Firebase Firestore для хранения статей
- Создает HTTP-сессию с пользовательским User-Agent

**Шаг 1.2: Проверка зависимостей**
- Проверяет наличие `OPENAI_API_KEY`
- Проверяет наличие `firebase_key.json`
- Инициализирует множество для отслеживания уникальных статей

## 📡 **2. Парсинг RSS-лент**

**Шаг 2.1: Загрузка списка источников**
- Читает файл `feeds.txt` со списком RSS-лент
- Игнорирует строки, начинающиеся с `#` (комментарии)
- Обрабатывает каждую RSS-ленту по очереди

**Шаг 2.2: Парсинг отдельной RSS-ленты**
- Загружает RSS-ленту через HTTP-запрос
- Парсит XML с помощью `feedparser`
- Извлекает метаданные ленты (название, описание, ссылка)

**Шаг 2.3: Обработка каждой новости**
Для каждой новости извлекает:
- **Заголовок** (`title`)
- **Ссылку** (`link`) 
- **Описание** (`summary` или `description`)
- **Дату публикации** (`published`, `updated`)
- **Изображение** (из различных источников: `media_content`, `media_thumbnail`, `enclosures`, `links`, HTML-контент)
- **Категории/теги** (`tags`, `category`)

**Шаг 2.4: Извлечение изображений**
Проверяет изображения в следующем порядке:
1. `media:content` (самый надежный)
2. `media:thumbnail`
3. `enclosures` (вложения)
4. `links` с типом image
5. HTML-контент в `summary`/`description`/`content`
6. HTML-контент в заголовке

## 🔍 **3. Фильтрация новостей через LLM (УЛУЧШЕННАЯ СИСТЕМА)**

**Шаг 3.1: Проверка уникальности**
- Создает хеш из ссылки и заголовка статьи
- Проверяет, не обрабатывалась ли статья ранее
- Проверяет дубликаты в Firebase

**Шаг 3.2: LLM-фильтрация (НОВАЯ ВЕРСИЯ)**
Отправляет в OpenAI GPT-4o-mini структурированный промпт для оценки релевантности:

```
Ты помощник редакции русскоязычного новостного сайта в Испании.

Оцени, будет ли следующая новость полезна или интересна для русскоязычных мигрантов, живущих в Испании.

**КРИТЕРИИ ОЦЕНКИ:**

✅ **ОДОБРЯЙ** если новость касается:
- Миграции, виз, ВНЖ, гражданства
- Аренды и покупки жилья в Испании
- Законодательства, налогов, бюрократии
- Рынка труда, зарплат, вакансий
- Образования, медицины, соц. служб
- Культурных событий, праздников, местных конфликтов
- Экстренных происшествий (землетрясения, протесты, пожары)
- Изменений в законах, влияющих на мигрантов

❌ **ОТКЛОНЯЙ** если новость:
- Не связана с Испанией географически
- О других странах (Украина, Россия, США) без связи с Испанией
- Международная политика без влияния на Испанию
- Спорт, развлечения без местного контекста
- Абстрактные социальные истории без практической пользы
- Криминал, не влияющий на мигрантов напрямую

Ответь строго в JSON формате:
{
  "result": "✅ Интересно" или "❌ Не интересно",
  "reason": "Краткое пояснение: почему да или нет"
}
```

**Шаг 3.3: Обработка JSON-ответа**
- Парсит структурированный JSON-ответ от LLM
- Извлекает результат (`result`) и объяснение (`reason`)
- Логирует решение с объяснением для отладки
- При ошибке парсинга использует fallback-логику

**Шаг 3.4: Fallback-логика**
Если JSON-парсинг не удался:
- Анализирует ключевые слова в ответе
- Ищет позитивные маркеры: `интересно`, `да`, `yes`, `true`, `✅`, `одобряю`, `полезно`
- Ищет негативные маркеры: `не интересно`, `нет`, `no`, `false`, `❌`, `отклоняю`
- В случае неопределенности - пропускает новость (более безопасно)

**Шаг 3.5: Принятие решения**
- Если `result` содержит `✅` или `Интересно` - новость одобряется
- Если `result` содержит `❌` или `Не интересно` - новость отклоняется
- Логируется объяснение решения для анализа

## 📄 **4. Извлечение полного текста**

**Шаг 4.1: HTTP-запрос к оригинальной статье**
- Отправляет GET-запрос к ссылке статьи
- Использует пользовательский User-Agent для обхода блокировок
- Обрабатывает различные кодировки

**Шаг 4.2: Парсинг HTML**
- Удаляет ненужные элементы: `script`, `style`, `nav`, `header`, `footer`, `aside`
- Удаляет рекламные блоки по CSS-селекторам
- Ищет основной контент через BeautifulSoup

**Шаг 4.3: Извлечение текста**
- Пробует найти контент через CSS-селекторы: `article`, `[class*="content"]`, `[class*="article"]` и др.
- Если не найден - использует `readability-lxml`
- Очищает текст от лишних пробелов и пустых строк
- Проверяет минимальную длину (50 символов)

## 🤖 **5. Обработка через LLM (перевод и адаптация)**

**Шаг 5.1: Подготовка промпта**
Отправляет в OpenAI GPT-4o-mini детальный промпт для создания статьи в стиле Meduza/The Village/Tinkoff Journal:

```
Ты опытный журналист, который пишет для русскоязычных мигрантов в Испании.

**🎯 КЛЮЧЕВОЕ ТРЕБОВАНИЕ:**
Многие имена, места и события могут быть незнакомы мигрантам. ОБЯЗАТЕЛЬНО объясняй каждый незнакомый термин простыми словами!

**Как писать:**
- Простыми словами, как будто объясняешь другу за чашкой кофе
- Избегай канцеляризмов и официальных оборотов
- Используй короткие предложения и абзацы
- Добавляй личные местоимения (мы, вы, они)
- Находи интригу даже в сухих новостях
```

**Шаг 5.2: Генерация структурированного контента**
LLM создает JSON с полями:
- `title` - короткий, понятный заголовок
- `description` - краткое описание (1-2 предложения)
- `content` - основная статья с подзаголовками `##`
- `tags` - 3-5 ключевых слов
- `pubDate` - дата публикации
- `author` - "Авто-редакция"
- `image` - URL изображения
- `slug` - URL-дружественное название
- `category` - "news"

**Шаг 5.3: Обработка ответа**
- Извлекает JSON из ответа LLM
- Проверяет наличие обязательных полей
- Добавляет значения по умолчанию для недостающих полей
- Сохраняет изображение из RSS в переведенную статью

## 💾 **6. Сохранение контента**

**Шаг 6.1: Сохранение в Markdown**
- Определяет директорию: `spain-news-portal/src/content/news` или `spain-news-portal/src/content/articles`
- Создает имя файла в формате: `YYYY-MM-DD-slug.md`
- Формирует frontmatter с метаданными
- Сохраняет файл с полным содержимым

**Шаг 6.2: Сохранение в Firebase**
- Создает уникальный ID на основе хеша ссылки и заголовка
- Сохраняет в коллекцию `articles` с полями:
  - `title`, `description`, `content`, `tags`
  - `link`, `published`, `image`, `category`
  - `source_feed`, `source_link`, `created_at`

## 📱 **7. Генерация Telegram-постов**

**Шаг 7.1: Создание промпта для Telegram**
Отправляет в OpenAI GPT-4o-mini промпт для создания Telegram-поста:

```
Ты пишешь посты для Telegram-канала, где публикуются новости для русскоязычных мигрантов в Испании.

**🎯 КЛЮЧЕВОЕ ТРЕБОВАНИЕ:**
Многие имена, места и события могут быть незнакомы мигрантам. ОБЯЗАТЕЛЬНО объясняй каждый незнакомый термин простыми словами!

**📏 СТРОГОЕ ТРЕБОВАНИЕ ПО ДЛИНЕ:**
Пост ДОЛЖЕН быть ровно до 1000 символов включительно. Не больше!

**🎨 ФОРМАТИРОВАНИЕ:**
- **Заголовок** выделяй жирным: **Название статьи**
- **Ключевые моменты** в тексте тоже выделяй жирным: **важная информация**
```

**Шаг 7.2: Структура Telegram-поста**
1. **🧲 Заголовок** (жирным, в одну строку)
2. **🧾 Краткий и насыщенный текст** (2-4 абзаца)
3. **🔗 Ссылка на полную статью**: `https://example.com/news/{slug}/`
4. **💬 Вопрос или призыв к обсуждению**

**Шаг 7.3: Контроль длины**
- Проверяет длину сгенерированного поста
- Если превышает 1000 символов - обрезает с сохранением ссылки и призыва к действию
- Резервирует место для обязательных элементов

## 📤 **8. Отправка в Telegram**

**Шаг 8.1: Подготовка к отправке**
- Получает `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` из переменных окружения
- Проверяет наличие изображения в статье
- Создает экземпляр Telegram бота

**Шаг 8.2: Попытка отправки с изображением**
- Пытается отправить фото с подписью через `bot.send_photo()`
- Использует Markdown-форматирование
- Если не удается - переходит к fallback

**Шаг 8.3: Fallback - только текст**
- Отправляет только текстовое сообщение через `bot.send_message()`
- Отключает предварительный просмотр ссылок
- Использует Markdown-форматирование

## 📊 **10. Кластеризация новостей (НОВАЯ ФУНКЦИЯ)**

**Шаг 10.1: 2-этапный пайплайн кластеризации**
- **Этап 1**: Разбиение анонсов на батчи по 20 штук
- **Этап 2**: Семантическая кластеризация каждого батча через LLM
- **Этап 3**: Объединение похожих кластеров между батчами
- **Этап 4**: Сохранение кластеров в Firebase

**Шаг 10.2: LLM-кластеризация**
Отправляет в OpenAI GPT-4o-mini промпт для группировки новостей:

```
Ты журналист. Ниже {len(batch)} новостных анонсов.

Сгруппируй их по смыслу — новости об одном и том же событии должны быть в одном кластере.

**ПРАВИЛА КЛАСТЕРИЗАЦИИ:**
- Объединяй новости об одном событии/теме
- Учитывай географическую близость (например, новости из одного города)
- Учитывай временную близость (новости за последние дни)
- Разделяй разные аспекты одной темы (например, законопроект и его принятие)

**ФОРМАТ ОТВЕТА:**
Для каждого кластера создай объект с полями:
- "topic_summary": краткое описание темы (1-2 предложения)
- "sources": массив объектов с полями "title", "link", "summary"
- "combined_context": объединенный текст важных деталей из всех источников

Ответь строго в формате JSON-массива объектов кластеров.
```

**Шаг 10.3: Обработка кластеров**
- Парсинг JSON-ответа от LLM (с поддержкой markdown-разметки)
- Создание объектов `NewsCluster` с уникальными ID
- Fallback-логика при ошибках парсинга
- Сохранение в коллекцию `news_clusters` в Firebase

**Шаг 10.4: Интеграция с основным пайплайном**
- Опциональное использование через флаг `--cluster`
- Режим работы только с кластерами `--clustered-only`
- Преобразование кластеров в формат статей для дальнейшей обработки

10. **Дубликат-контроль** - избежание повторных публикаций
11. **Изображения** - автоматическое извлечение и использование
12. **Подробное логирование** - анализ решений и отладка

14. **Объединение контента** - создание более полных статей из кластеров
